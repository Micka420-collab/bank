# Modèle de menace et défenses

Bank contient l'historique bancaire complet d'un foyer, ses revenus et sa situation sociale. Chaque menace ci-dessous
a au moins une défense testée (référence du test entre parenthèses).

## Ce qu'on protège

| Donnée | Où | Protection |
|---|---|---|
| IBAN, uid de compte DSP2, session DSP2, secret TOTP, profil du foyer, résultats de simulation | SQLite | AES-256-GCM par champ, contexte lié en AAD (`test_context_binding_blocks_column_swap`) |
| Mots de passe | SQLite | Argon2id 64 MiB, t=3, p=2, re-hash automatique (`test_hash_and_verify`) |
| Jetons de session | SQLite | Seule l'empreinte SHA-256 est stockée (`test_session_token_stored_hashed_and_idle_expiry`) |
| Jetons d'agent IA (`bnk_…`) | SQLite | Empreinte SHA-256 seule, affichés une fois, expiration ≤ 365 j (`test_token_is_stored_hashed_and_authenticates`) |
| Jeton Conso API et PRM (Linky) | SQLite | AES-256-GCM par champ ; jamais dans l'audit, l'export ni le dossier de l'agent (`test_linky_connect_backfill_sync_and_insights`, `test_export_includes_energy_and_documents`) ; journaux httpx/httpcore ramenés au niveau avertissement pour que l'URL sortante (PRM, uid de compte DSP2) n'y figure pas (`test_prm_never_reaches_the_logs`) |
| Identifiant et mot de passe d'application IMAP, expéditeur et objet des PDF proposés | SQLite | AES-256-GCM par champ ; jamais dans l'API (seul un indice « mi…@domaine » ressort), l'audit, l'export ni une erreur (`test_linking_needs_bank_password_and_a_working_login_and_never_returns_secrets`) |
| Identifiant d'application et clé privée RSA Enable Banking saisis dans l'assistant | SQLite | AES-256-GCM par champ ; jamais dans l'API (indice « …3b4a59 » et empreinte SHA-256 de la clé publique seulement), l'audit, l'export ni une erreur ; une configuration du serveur (`.env` + fichier de clé) prime et ne se modifie pas depuis l'application (`test_wizard_saves_checks_and_serves_the_new_client_live`, `test_server_configuration_wins_and_is_not_editable`) |
| Identifiants du contrat Powens (domaine, client_id, client_secret), jeton permanent et identifiant de l'utilisateur Powens | SQLite | AES-256-GCM par champ (le domaine en clair) ; jamais dans l'API (domaine, indice « …3977 » et empreinte HMAC du secret sous la clé du serveur seulement), l'audit, l'export (domaine, indice, empreinte) ni les messages d'erreur (seul le code d'erreur Powens est repris) ; le secret ne part que dans le corps de `/auth/init` et `/auth/renew` (`test_secret_never_leaves_bank`, `test_client_rejects_bad_ids_and_hides_error_bodies`) |
| Adresse privée de l'agenda de travail, titres des événements, modèle de paie | SQLite | AES-256-GCM par champ ; l'adresse n'est jamais renvoyée par l'API ni exportée (`test_planning_url_source_is_fetched_safely`, `test_export_includes_planning_shifts_not_the_url`) ; HERMÈS ne voit que la paie prévue et son explication, jamais l'agenda (`test_planning_file_connect_model_and_prediction_feed_the_month`) |
| Faits des documents officiels (RFR, parts, droits CAF, fin de droits) | SQLite | AES-256-GCM ; identifiants (numéro fiscal, NIR, allocataire, adresse, IBAN) détectés et jetés avant tout stockage (`test_avis_impot_keeps_figures_and_discards_identifiers`) |
| Dossier « Ma situation », propositions de l'agent | SQLite | AES-256-GCM par champ, historique des réponses chiffré |
| Libellés et montants | SQLite | En clair (recherche, catégorisation) : volume local + sauvegardes chiffrées avec `age` |
| Clé maîtresse | `./secrets` (640, groupe 10010) | Jamais en base, jamais dans l'environnement du process en prod (`*_FILE`) |

Clés dérivées par HKDF, une par usage (chiffrement, index aveugle, jetons signés, chaîne d'audit).

## Menaces et réponses

| Menace | Défense |
|---|---|
| Quelqu'un sur le LAN « réclame » l'instance avant toi | Création du compte exige `BANK_SETUP_TOKEN` (`test_setup_requires_token_and_strong_password`) |
| Force brute / bourrage d'identifiants | Rate-limit nginx + backend, verrouillage exponentiel jusqu'à 24 h persisté même en cas d'échec (`test_generic_errors_and_lockout`, `test_rate_limit`). La limite stricte de nginx (10/min) ne vise que ce qui porte un secret (connexion, code, installation, mot de passe, export) ; les lectures de session faites à chaque ouverture et la déconnexion suivent la limite générale, pour qu'un rechargement ne ressemble jamais à une panne — et une 429 s'affiche « patiente une minute », jamais « serveur en panne » |
| Énumération d'identifiants | Message identique, coût Argon2 payé même pour un utilisateur inconnu |
| Vol du mot de passe | TOTP avec anti-rejeu par pas temporel, 10 codes de secours à usage unique (`test_full_mfa_flow_with_replay_protection_and_recovery`) |
| CSRF | Cookies `SameSite=Strict`, jeton double-submit comparé à une empreinte, vérification de l'en-tête Origin (`test_csrf_and_origin_enforced`) |
| XSS | CSP `script-src 'self'` sans inline, React sans `dangerouslySetInnerHTML`, QR code rendu via `<img>` (vérifié sans violation dans Chromium) |
| Vol de cookie | `__Host-` + HttpOnly + Secure, expiration d'inactivité 30 min et absolue 12 h, révocation globale au changement de mot de passe (`test_password_change_revokes_other_sessions`) |
| DNS rebinding | Liste blanche d'hôtes (`test_untrusted_host_rejected`) |
| Fichier d'import malveillant | Taille bornée (nginx + middleware + lecture), aucun parseur XML (pas de XXE, `test_ofx_v2_xml_is_not_vulnerable_to_xxe`), caractères de contrôle supprimés |
| Injection SQL | ORM paramétré partout, échappement des jokers LIKE (`test_search_filters_and_like_escaping`) |
| Fuite d'un code d'autorisation bancaire ou d'un identifiant dans les logs | Journal d'accès maison sans query string, uvicorn sans access log, httpx silencieux sous le niveau avertissement (`test_prm_never_reaches_the_logs`) |
| Rejeu du retour bancaire | `state` aléatoire à usage unique, durée de vie 15 min, stocké sous forme d'empreinte (`test_connect_callback_sync_reconcile_revoke`, `test_expired_state_rejected`) |
| Falsification de l'historique d'activité | Chaîne HMAC (clé hors base) : modification, suppression, insertion ou recalcul détectés (`test_audit_chain_*`) ; tête de chaîne ancrée dans les logs du conteneur contre la troncature |
| Fuite de la situation fiscale | Moteur OpenFisca sur un réseau Docker sans Internet, jeton partagé, liste blanche de variables |
| Conteneur compromis | Non-root, FS en lecture seule, toutes capabilities retirées, `no-new-privileges`, limites mémoire/pids, réseaux segmentés |
| Données en cache | `Cache-Control: no-store` sur l'API ; le service worker ne met jamais `/api` en cache |
| Export de toutes les données | Re-saisie du mot de passe, rate-limit, journalisé |
| « Enregistré » dit avant que ce soit vrai | La transaction d'une requête est validée **avant** l'envoi de la réponse (portée `function` de la dépendance base) : un 201 signifie que la ligne est écrite, un commit qui échoue devient une erreur visible, et la requête suivante — ou un autre processus comme le gardien MCP — ne peut pas lire un état antérieur (`test_the_row_is_committed_before_the_response_leaves`) |
| Fuite d'erreurs internes | Gestionnaire global : message générique, détails seulement dans les logs ; erreurs de validation sans les valeurs reçues (`test_validation_errors_never_echo_input`) |
| Fuite de la clé OpenRouter | Chiffrée en base (AES-256-GCM), ajout protégé par ton mot de passe, jamais renvoyée par l'API (seul le préfixe `sk-or-v1-ab12…`), absente des exports, du journal et des messages d'erreur ; transmise uniquement dans l'en-tête `Authorization` vers `openrouter.ai`, sans redirection suivie (`test_configure_stores_the_key_encrypted_and_never_returns_it`) |
| Données envoyées au modèle de langage | Dossier anonymisé par défaut (aucun nom de particulier, IBAN, téléphone ni long numéro), mode « chiffres seuls » sans aucun libellé ni mémoire ; le journal d'audit n'a que modèle, jetons, coût et noms d'outils, jamais le texte échangé (`test_ask_grounds_the_model_on_an_anonymised_dossier_and_logs_no_content`, `test_aggregates_privacy_turns_memory_off`) |
| Conversations conservées | Chiffrées champ par champ (AES-256-GCM) ; sans accord « mémoire », effacées à la fermeture ou après 6 h d'inactivité ; avec accord, gardées selon la durée choisie (30 j à 3 ans, ou sans limite) puis purgées ; exportables, effaçables une à une ou toutes (mot de passe) (`test_without_consent_nothing_is_learned_and_the_conversation_vanishes`, `test_purge_respects_the_retention_choice`, `test_housekeeping_closes_reviews_and_purges`) |
| Mémoire empoisonnée (injection qui s'installe d'une conversation à l'autre) | Filtre strict à l'écriture **et** à l'injection : consignes (« ignore les règles », changement de rôle, dissimulation), caractères invisibles ou bidirectionnels, HTML, liens, commandes réseau, secrets, IBAN, carte (Luhn), n° de sécurité sociale, téléphone, e-mail, longs numéros ; une entrée modifiée hors de Bank est neutralisée « [BLOQUÉ] » ; faits déclaratifs, jamais des consignes ; relecture automatique limitée aux ajouts, corrections et suppressions soumises à ta validation (avec détection d'une cible modifiée entre-temps) ; entrées épinglées intouchables ; carnets bornés (1 500 et 2 200 caractères) (`test_scan_blocks_identifiers_secrets_and_injections`, `test_a_tampered_entry_is_never_injected`, `test_review_learns_every_eight_questions_and_stages_corrections`) |
| Coût incontrôlé d'un modèle | Plafond de crédits par mois et d'appels par jour vérifiés avant **chaque** appel (outils et relecture compris), au plus 4 tours d'outils puis une réponse sans outil, 3 échecs d'écriture en mémoire au plus, limiteur de débit, réponse bornée en taille et en temps (`test_caps_stop_the_spending`, `test_tool_rounds_are_bounded_and_caps_checked_between_them`) |
| Injection via un libellé d'opération ou un résultat d'outil | Dossier et résultats d'outils balisés comme données ; trois outils seulement : sa propre mémoire (bornée, filtrée, chaque écriture affichée et annulable), la recherche dans vos conversations (lecture) et le calcul d'achat de Bank (lecture) ; aucun outil ne classe, ne déplace ni n'envoie quoi que ce soit ; arguments validés, outil inconnu refusé ; les propositions d'enveloppes sont filtrées sur la liste des enveloppes existantes (`test_refused_writes_are_explained_then_bounded`, `test_hints_are_proposed_once_validated_and_feed_the_cards`) |
| Consentement | Registre par finalité (mémoire de l'assistant, lecture de documents par un modèle, pièces sensibles, veille), texte versionné : un texte modifié redemande ton accord ; retrait à effet immédiat, y compris au milieu d'une conversation ; chaque accord et retrait journalisé (`test_consents_are_listed_versioned_and_revocable`, `test_revoking_consent_stops_memory_mid_conversation`) |
| Fichier piégé déposé au coffre (image ou PDF forgé, « bombe » de décompression) | Format reconnu aux premiers octets (jamais au nom), 12 Mo par fichier et 40 Mo par envoi ; nettoyage, lecture des PDF et OCR dans des processus enfants confinés (Python isolé, environnement vide, limites CPU, mémoire, fichiers et processus, tués au-delà d'un délai, 2 lectures à la fois) ; Pillow plafonné à 50 Mpx ; Tesseract ne lit que l'image réencodée par Bank (`test_transparent_png_and_hostile_images`, `test_encrypted_or_broken_pdfs_are_refused`) |
| Métadonnées des photos (position GPS, appareil, date) | Chaque photo est redressée puis réencodée en JPEG sans EXIF, XMP ni profil ; seule cette version est conservée (`test_photos_lose_their_metadata_and_stand_upright`) |
| Fichiers du coffre au repos | Chiffrés AES-256-GCM avec l'identifiant du document en données associées (un fichier recopié sous un autre identifiant ne se déchiffre pas) ; empreinte de dédoublonnage à clé (HMAC), inexploitable pour tester la présence d'un document connu ; suppression avec pages SQLite écrasées (`secure_delete`) |
| Fichier déposé servi au navigateur | `nosniff`, CSP `sandbox` sur chaque fichier, PDF toujours en téléchargement (jamais ouvert dans l'origine de l'application), images réencodées par Bank ; accès journalisé |
| Pièces sensibles (identité, séjour, santé) | Sans ton accord « Pièces sensibles », le fichier est effacé dès qu'il est reconnu ; avec, seuls le type et la date d'expiration sont extraits (jamais un numéro) ; jamais envoyées à un modèle, même si un modèle les reconnaît après coup (`test_sensitive_documents_need_consent`, `test_assisted_reading_refusals`) |
| Valeurs inventées par un modèle | Lecture assistée sur accord explicite, document par document, interdite en mode « chiffres seuls » ; IBAN, e-mail, téléphone, n° de sécurité sociale et longs numéros masqués avant envoi ; une valeur n'est gardée que si sa citation existe mot pour mot dans le document **et** la contient ; jamais elle n'écrase une valeur lue ou corrigée (`test_assisted_reading_keeps_only_quoted_values`) |
| Données laissées dans le navigateur | Le stockage local ne contient que des préférences d'affichage (`bank:theme`, `bank:today-details`), l'identifiant retenu pour la connexion rapide (`bank:username`, jamais le mot de passe) et l'état de l'onboarding (`bank:onboarding`) ; aucune donnée financière, aucun jeton |
| Démarche transmise sans toi ou deux fois | Bank n'a aucun moyen d'envoyer : il prépare, tu transmets ; « Je l'ai transmis » n'est accepté que pour le dossier validé, validation liée à l'empreinte du dossier complet (valeurs actives, pièces, lettre) et à chaque engagement coché ; tout changement l'annule ; empreinte d'envoi unique en base (double clic, deux onglets, dossier jumeau) (`test_approval_is_bound_to_the_exact_dossier`, `test_identical_dossiers_are_sent_only_once`) |
| Valeur fausse dans un dossier | Une valeur saisie qui contredit son justificatif bloque la préparation ; la valeur tirée d'un document suit ses corrections ; provenance affichée pour chaque champ (`test_a_value_contradicting_its_proof_blocks_until_corrected`) |
| Gain ou droit « inventé » | Montants tirés de tes opérations, de tes documents ou d'OpenFisca ; règles citées avec leur date ; constaté, estimé et supposé séparés ; un gain n'est « obtenu » que constaté et confirmé par toi, une seule fois ; un remboursement de soins n'est pas pris pour un remboursement de frais (`test_fees_over_the_caps_become_a_complaint_then_a_confirmed_refund`, `test_fee_refund_recognition`) |
| Veille qui vise le réseau du serveur (SSRF, DNS rebinding) | https et port 443 seulement, sans identifiants ; hôte résolu une fois, toutes ses adresses publiques, puis connexion **épinglée** sur l'adresse vérifiée avec le certificat contrôlé pour le nom (SNI) ; chaque redirection (3 au plus) recontrôlée ; noms locaux refusés (`test_check_url_refuses_anything_local_or_unusual`, `test_dns_answers_are_checked_too`, `test_fetch_pins_the_checked_address_and_keeps_the_name_for_tls`, `test_fetch_follows_only_safe_redirects`) |
| Flux piégé (XXE, « billion laughs », réponse géante, bombe gzip) | XML lu avec defusedxml (DTD, entités et références externes interdites) ; 2 Mo au plus, décompression bornée en sortie, délai borné ; texte réduit au texte brut, liens réduits aux adresses http(s) côté serveur **et** navigateur, ouverts en `noopener` (`test_hostile_feeds_are_refused_or_neutralised`, `test_fetch_bounds_size_time_and_compression`) |
| Fuite de ta situation vers une source surveillée | Requêtes anonymes (aucun paramètre te concernant) ; thèmes rapprochés de ta situation sur ton serveur ; veille désactivable par l'accord « Veille » (`test_watch_respects_consent_and_schedule`) |
| Donnée de référence périmée présentée comme en vigueur | Taux, barèmes et sources portent une date de prochaine vérification ; dépassée, l'écran Veille et le tableau de bord le signalent (`test_reference_data_is_flagged_when_it_may_have_changed`) |
| Bouton, graphique ou schéma « inventé » par le modèle dans le chat | Le modèle ne fabrique aucun bloc : il demande, Bank construit. Un bouton vient d'un **catalogue** calculé à chaque question (écrans existants, cartes « Bank te demande », questions suivantes) — une clé inconnue est ignorée et comptée ; un graphique est dessiné par Bank avec **ses** données (le modèle choisit un jeu et une période, reçoit les chiffres pour les commenter) ; un schéma est le seul contenu rédigé par le modèle : borné (12 boîtes, 48 caractères, pas de lien, pas de caractère de contrôle ni bidirectionnel), présenté comme « proposé par le modèle » ; tout bloc est revalidé à la sortie vers le navigateur et conservé chiffré avec la conversation (`test_buttons_come_from_the_catalogue_chart_from_bank_and_blocks_are_kept`, `test_diagram_block_is_bounded_and_ignores_broken_edges`) |
| Barème public relu qui fausse un calcul, ou change en silence (CRE, Caisse des Dépôts, INSEE, OpenFisca) | **Choix de l'accord** : rien te concernant ne part (adresses fixes, sans paramètre personnel), mais quatre serveurs de plus voient l'adresse de ton serveur une fois par mois ; comme tout nouveau flux sortant, c'est donc un accord à part, « Barèmes tenus à jour », **désactivé par défaut** ; sans lui, rien ne part et Bank garde le `rates.json` livré. Téléchargeur durci (1 Mo et 30 s par fichier), réseau hors transaction ; chaque valeur lue est bornée, datée et gardée avec l'adresse exacte de la source et la date de relève ; XML sans DTD ni entités. Une valeur ne remplace celle du fichier que si la source la date au moins du même jour (une source en retard ne fait jamais reculer un taux) et passe par une couche au-dessus de `rates.json`, qui reste le repli et reprend la main s'il est plus récent. Chaque changement est noté dans la Veille et au journal (ancienne → nouvelle valeur, source) et s'écarte d'un geste dans Réglages › Barèmes ; une relève ratée garde les valeurs précédentes et le dit (`test_nothing_leaves_without_consent`, `test_proposal_fixes_the_subscription_gap_and_nothing_else`, `test_overlay_never_beats_a_newer_file_and_ignores_unknown_paths`, `test_failed_fetch_keeps_the_previous_values_and_says_so`, `test_revert_returns_to_the_file_and_is_not_reapplied`, `test_parsers_are_defensive`) |
| Adresse qui fuit (géocodage, calendrier scolaire) | Deux accords à part, **désactivés par défaut** : « Ton adresse située sur la carte » (seule l'adresse que tu tapes part, vers la Géoplateforme de l'IGN ; résultat — commune, code INSEE, coordonnées, académie — chiffré, une ligne ; le journal note la précision, jamais l'adresse) et « Jours fériés et vacances scolaires » (partent la zone, le code du département puis le nom de l'académie, jamais l'adresse ni la commune ; jours fériés et vacances gardés chiffrés, datés, avec leur source). Téléchargeur durci (500 Ko, 20 s), réseau hors transaction, réponses bornées et vérifiées ; une relève ratée garde la précédente et le dit ; sans accord, la prévision ne décale rien. Effacer l'adresse efface aussi les vacances de l'académie (`test_nothing_leaves_without_consent`, `test_geocoding_sends_only_the_typed_address_and_keeps_it_encrypted`, `test_calendar_feeds_the_forecast_and_a_failure_keeps_the_previous`, `test_parsers_are_defensive`) |
| Mail d'un organisme qui en dit trop (documents à récupérer) | Seuls l'expéditeur, l'objet, la date et l'identifiant d'un message déjà lu par la boîte en lecture seule servent, jamais son texte ; domaines reconnus exactement (« impots.gouv.fr.exemple » ne passe pas) ; un expéditeur usurpé ne crée au pire qu'une tâche, dont le lien est toujours la page d'entrée vérifiée par Bank, jamais un lien du mail ; objet et document attendu chiffrés ; rien ne part, Bank ne se connecte à aucun compte de l'État et n'en garde aucun identifiant (`test_a_notice_without_attachment_becomes_a_task`, `test_mail_notice_becomes_a_task_that_closes_when_the_pdf_is_filed`) |
| Commune ou adresse qui fuit (valeur du logement, DVF) | Accord explicite « Valeur de ton logement (ventes DVF) » ; seul le fichier public de la commune est demandé (aucun paramètre, ni adresse, ni surface, ni section : le filtre par section se fait ici), et la recherche de commune n'envoie que le nom ou le code postal tapé ; téléchargeur durci, 40 Mo et 60 s au plus par fichier ; description et ventes réduites chiffrées (AES-256-GCM), le journal d'audit ne note que les noms des champs changés ; une extraction par trimestre et trois essais par jour au plus, même en effaçant puis redécrivant ton logement ; téléchargement hors transaction (`test_estimate_cache_and_quarter_rollover`, `test_removing_the_home_keeps_the_daily_cap`, `test_download_happens_outside_the_write_lock`, `test_nothing_leaves_without_consent`, `test_commune_search_sends_only_what_you_typed`, `test_profile_is_encrypted_and_audit_says_what_changed_not_the_values`) |
| Requête web qui te trahit (recherche de l'assistant) | Accord explicite « Recherche web par l'assistant » (retirable, effet immédiat : l'outil disparaît) ; moteur choisi par toi, mot de passe exigé (SearXNG chez toi, ou Brave avec une clé chiffrée jamais réaffichée) ; la requête rédigée par le modèle est **nettoyée** avant de partir (IBAN, e-mail, téléphone, longs numéros, noms de personnes retirés) et un secret (carte, IBAN, mot de passe) l'arrête net ; trois recherches par question, plafond par jour ; le journal compte le moteur et le nombre de résultats, jamais la requête (`test_query_is_scrubbed_and_secrets_stop_it`, `test_web_search_needs_a_provider_and_consent_then_cites_sources_and_reads_pages`, `test_search_consent_withdrawal_cap_and_brave`) |
| Page lue par l'assistant qui vise ton réseau, ou qui lui dicte quoi faire | Le modèle ne choisit jamais une adresse, seulement un numéro de résultat ; la page passe par le téléchargeur durci de la veille (https, port 443, adresses publiques, redirections recontrôlées, 1,5 Mo et 15 s) ; le HTML est réduit à son texte (scripts, styles et balises retirés, 8 000 caractères) et balisé comme des données, jamais des consignes ; seuls `https` et sans identifiants sont acceptés comme sources (`test_html_to_text_drops_scripts_and_keeps_readable_lines`, `test_results_are_normalised_https_only_deduplicated_and_capped`) |
| Notification qui révèle ta situation en chemin, ou abonnement qui vise ton réseau | Web Push à la norme, écrit à la main : message chiffré pour la clé de ton navigateur (RFC 8291, « aes128gcm », vecteur d'essai de la norme reproduit au bit près) et signé par ton serveur (VAPID ES256, RFC 8292) ; le service de notification ne voit qu'un blob ; l'abonnement envoyé par le navigateur est vérifié (https, service public, jamais ton réseau) et son adresse chiffrée en base, indexée par empreinte ; accord « Notifications sur ce téléphone » révocable ; un 404/410 du service retire l'appareil ; huit appareils au plus ; le journal n'a que l'identifiant d'appareil (`test_rfc8291_test_vector_matches_bit_for_bit`, `test_subscribe_needs_consent_and_a_public_https_endpoint_then_a_test_notification_is_readable`) |
| Réponse en direct qui fuit ou qui s'emballe | Le flux SSE de l'assistant passe par les mêmes plafonds et le même journal que la réponse en un bloc ; la transaction vit dans le fil de travail le temps de la réponse ; une erreur arrive comme un événement lisible, jamais une trace ; nginx ne tamponne pas et borne la durée (`test_stream_endpoint_reports_errors_as_an_event`) |

## Agents IA (serveur MCP `/mcp`)

Un agent est un utilisateur non fiable par construction : il peut se tromper, ou lire un texte piégé (un libellé
d'opération qui lui donne des « consignes »). Bank ne lui fait donc confiance que pour ce qu'il ne peut pas abîmer.

| Menace | Défense |
|---|---|
| Accès sans jeton, jeton volé ou révoqué | Jeton vérifié en base à chaque requête HTTP **et** à chaque appel d'outil ; révocation immédiate (`test_revocation_is_immediate`) ; liste d'IP par jeton (`test_ip_allowlist`) |
| Agent qui déplace de l'argent | Aucun outil de Bank ne le permet ; Bank n'a qu'un accès DSP2 en lecture (`test_initialize_and_catalogue`). Un mouvement crypto exécuté ailleurs passe par ta confirmation, ou par le pilote automatique, éteint par défaut et borné de toutes parts (section suivante) |
| Agent qui s'auto-promeut (élargit son mandat, lève une ligne rouge) | Questions du mandat refusées côté MCP **et** côté service, quel que soit le chemin (`test_agent_records_answers_but_never_its_mandate`, `test_mandate_cannot_be_written_by_an_agent_even_internally`) |
| Injection de consignes via un libellé | Libellés livrés comme champs de données, consignes explicites dans le dossier et la compétence ; aucune action à effet sans validation humaine (`test_transactions_respect_privacy_mode`) |
| Changement de réglage non voulu | Propositions typées et validées strictement, file bornée (20), dédoublonnées, expirées après 14 j, appliquées par le code de Bank après ton clic ; une règle proposée affiche le nombre d'opérations touchées et son motif est validé après normalisation (`test_proposals_are_strictly_validated`, `test_pending_queue_is_bounded`, `test_rule_patterns_are_validated_after_normalisation`) |
| Agent qui réécrit ta situation ou fausse la prévision | Il ne peut ni écraser une réponse que tu as donnée, ni écrire une dépense prévue : il les propose (`test_agent_cannot_overwrite_user_answers_nor_forecast_inputs`) ; ses classements sont marqués « agent », jamais appris, jamais par-dessus les tiens (`test_agent_categorization_is_marked_and_never_overrides_the_user`) |
| Session volée qui crée un jeton | Mot de passe redemandé, essais limités, refus journalisés (`test_token_creation_requires_password`) |
| Simulation en boucle | Résultat de moins de 6 h réutilisé, 4 simulations/h par jeton, une seule à la fois (`test_simulation_is_reused_and_profile_errors_never_echo_values`) |
| Fuite de données personnelles vers un modèle distant | Anonymisation par défaut, qui échoue du côté sûr : la contrepartie d'un virement est un particulier sauf indice d'organisation ; IBAN quels que soient les séparateurs ; masquage jusque dans les preuves des valeurs détectées et les paliers du budget ; mode agrégats sans aucun libellé ; erreurs de validation jamais renvoyées avec les valeurs (`test_redaction_masks_personal_data`, `test_any_two_word_transfer_counterparty_is_masked`, `test_income_from_a_person_never_leaks_in_redacted_dossier`, `test_onboarding_status_respects_privacy`) |
| Abus de débit, boucle d'agent | 120 appels/min par jeton (API) + 5 r/s par IP (nginx) (`test_rate_limit_per_token`) |
| Inconnu qui écrit au robot d'une messagerie | Refus par défaut : aucune réponse (il n'apprend même pas que le robot est relié à Bank) ; seuls les comptes reliés par un code généré dans Bank après le mot de passe sont écoutés (code 8 caractères, 15 min, 5 essais, usage unique, empreinte salée seulement) ; chaque nouveau compte relié est annoncé aux autres (`test_a_full_conversation_on_telegram`, `test_codes_expire_lock_after_five_misses_and_serve_once`, `test_a_new_link_is_announced_to_the_other_accounts`) |
| Faux webhook WhatsApp, rejeu | Corps borné, signature HMAC-SHA256 de Meta vérifiée en temps constant avant toute lecture, numéro destinataire contrôlé, messages dédoublonnés par identifiant ; 404 sans rien dire quand rien n'est activé (`test_whatsapp_webhook_is_verified_before_anything`) |
| WhatsApp par QR code (ton numéro, passerelle non officielle) | Choix assumé du propriétaire (suspension possible, session qui voit tout). Passerelle jointe en local ou réseau privé seulement (adresse vérifiée, formes numériques abrégées comme `134744072` lues comme le résolveur), sans root dans Docker, jamais exposée (aucun port publié, nginx répond 404 sur son webhook, l'API refuse ce qui passe par le frontal), refusée si elle répond sans mot de passe ; webhook signé HMAC-SHA256 en temps constant ; **seule la conversation « Moi »** passe (message de toi, dans ta conversation, sur ton appareil) : le reste est écarté avant lecture, sans journal ni écriture ; réponses marquées d'un caractère invisible et identifiants retenus, jamais relues ; envoi vers un autre numéro refusé ; QR (servi en image, adresse de la passerelle jamais montrée) et « Délier » derrière le mot de passe ; un téléphone relié hors de Bank n'obtient rien. | Secret collé dans une messagerie | Carte (Luhn), IBAN, « mot de passe : … » repérés avant tout traitement : refusés, ni montrés au modèle ni gardés ; Bank ne demande jamais de secret (`test_secret_kind`) |

## Passkeys (WebAuthn)

| Menace | Défense |
|---|---|
| Fausse page de connexion qui récupère le mot de passe | Une passkey ne signe que pour le domaine et l'origine de l'adresse publique de Bank (`rpId`, `origin` vérifiés par le protocole) : une copie du site, même parfaite, n'obtient rien (`test_phishing_replay_and_missing_verification_are_refused`) |
| Rejeu d'une réponse capturée, authentificateur cloné | Défi aléatoire signé par Bank, valable cinq minutes et **à usage unique** ; compteur de signature qui doit croître ; vérification de l'utilisateur (code, biométrie) exigée à l'enregistrement comme à la connexion ; `userHandle` comparé à l'identifiant opaque de l'utilisateur |
| Ajout ou retrait d'une passkey depuis une session volée | Mot de passe exigé dans les deux cas, limité en débit, refus audités ; dix passkeys au plus ; le mot de passe reste exigé pour les gestes sensibles (pilote, export, jetons, nœuds crypto) (`test_register_with_password_then_login_without_it`, `test_removing_a_passkey_needs_the_password_and_closes_the_door`) |

| Connexion par passkey = un seul facteur ? | Une passkey avec vérification de l'utilisateur vaut deux facteurs (possession + biométrie ou code) ; la connexion est auditée comme une connexion forte (`mfa: true, passkey: <id>`) |

## Partage d'un papier par lien

Un papier du coffre peut sortir de chez toi par un lien : c'est la seule route du coffre sans session
(`POST /api/share/open`). Tout le reste (créer, lister, révoquer) exige ta session, le jeton CSRF et, pour créer,
ton mot de passe.

| Menace | Défense |
|---|---|
| Lien créé depuis une session volée | Mot de passe redemandé à chaque lien, limité en débit, refus audité `vault.share_denied` (`test_a_link_is_created_only_with_the_password`) |
| Le lien trahit le document | Jeton aléatoire de 256 bits, sans identifiant ni nom ; placé dans le fragment (`/#/recu/<jeton>`), il n'atteint ni les journaux du serveur ni un `Referer` ; Bank ne garde que son empreinte SHA-256 ; réponse au nom générique `document.pdf`, `attachment`, `no-store`, `X-Robots-Tag: noindex`, `Referrer-Policy: no-referrer` (`test_one_download_with_the_watermark_then_nothing`) |
| Aperçu de lien d'une messagerie qui « consomme » le téléchargement | La page du destinataire ne soumet le jeton qu'au clic, par `POST`, sans cookie (`credentials: omit`) ; un robot qui charge l'adresse ne reçoit que l'application |
| Deux téléchargements du même lien | Consommation par une seule mise à jour conditionnelle (`used_at IS NULL`, ni révoqué ni expiré, nombre de lignes vérifié), sous le verrou d'écriture : un seul gagnant (`test_two_simultaneous_downloads_cannot_both_succeed`) |
| Deviner si un lien a existé | Lien inconnu, expiré, consommé ou révoqué : même 404, même corps, aucun détail, y compris pour une requête malformée (pas de 422 de validation) (`test_expired_revoked_used_and_unknown_look_the_same`, `test_a_malformed_request_gets_the_same_answer`) ; 10 ouvertures par IP et par 5 minutes côté API, 10 par minute côté nginx (`test_opening_links_is_rate_limited`) |
| Le papier circule ensuite sans attache | Filigrane sur chaque page (en diagonale et en pied de page) : « Transmis à X le JJ/MM/AAAA par Bank — usage unique » ; une photo est d'abord mise en page en PDF ; le tout dans le processus enfant confiné qui lit déjà les PDF ; nom du destinataire nettoyé (contrôles et invisibles retirés, 60 caractères, accent hors police ramené à sa lettre de base, lettre que la police ne sait pas écrire refusée plutôt que retirée) ; posé dans la zone affichée (CropBox) et pied de page ajusté à la largeur (`test_a_photo_is_shared_as_a_watermarked_pdf`, `test_recipient_names_are_cleaned_for_the_watermark`, `test_the_watermark_stays_in_the_visible_part_of_the_page`) |
| Un partage bloque le reste de Bank | Le filigrane (jusqu'à 25 s) se fait avant toute écriture : le verrou d'écriture de SQLite n'est pris qu'après (`test_the_rest_of_bank_can_write_while_a_copy_is_stamped`) |
| Copie qui traîne | Copie filigranée chiffrée (AES-256-GCM, identifiant du partage en données associées), effacée au téléchargement, à la révocation, ou à l'entretien horaire après l'expiration ; supprimer le document emporte ses liens ; le journal (destinataire chiffré, dates) reste |
| Partage à ton insu | Création, téléchargement (avec l'IP), révocation et tentatives sur un lien qui ne sert plus sont dans la chaîne d'audit (`vault.share_*`), sans jeton ni nom du destinataire |

Pour un destinataire extérieur, ton reverse proxy n'a à exposer que `/`, `/assets/`, `/icon.svg` et
`/api/share/open` : le reste de `/api` n'est pas exposé. La page du destinataire n'enregistre pas le service worker
et ne demande pas le manifeste de l'application.

## Crypto et pilote automatique

Le pilote automatique est le seul chemin par lequel un agent bouge de l'argent sans te redemander : il est
conçu comme une barrière qu'un agent manipulé (texte piégé, nom de jeton, faux support) ne peut pas franchir.

| Menace | Défense |
|---|---|
| Pilote activé par une session volée | Mot de passe **et** code TOTP s'il est activé : relu sous verrou d'écriture et consommé avant tout le reste (même si le cadre est refusé, il ne resert pas), essais limités, refus audités (`test_api_needs_password_and_second_factor_but_stopping_needs_nothing`, `test_api_consumes_the_second_factor_even_when_the_frame_is_refused`) |
| Un autre agent, ou un jeton recréé du même nom | Le mandat suit l'identifiant d'UN jeton ; révoquer ce jeton coupe le pilote (`test_expiry_and_token_changes_end_the_pilot`, `test_revoking_the_token_in_bank_stops_the_pilot`) |
| Bait-and-switch : plus exécuté qu'autorisé | Montant rapporté au-delà d'1 € de marge : arrêt immédiat (`test_bait_and_switch_more_executed_than_authorized_stops_everything`) |

## Hors périmètre (assumé)

- Compromission de nimbus avec accès root : la clé maîtresse est lisible. Défense : disque chiffré (LUKS), mises à jour.
- Un seul worker uvicorn : le rate-limit en mémoire est exact ; avec plusieurs workers il faudrait un stockage partagé.
- La liste d'IP d'un jeton repose sur `X-Forwarded-For` posé par ton reverse proxy : nginx ne le croit que depuis
  la passerelle du réseau `edge` (sous-réseau fixe 172.31.250.0/29), par où arrive le port publié sur 127.0.0.1.
  Garde `BANK_BIND=127.0.0.1` : publié sur le LAN, le port laisserait n'importe qui forger cet en-tête. C'est une
  défense en profondeur, le jeton reste la barrière principale.
- Ce que fait HERMÈS de ses propres données (mémoire, journaux) relève de sa configuration, pas de Bank.
